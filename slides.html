3 · AGENT ARCHITECTURE

Planner ↔ Executor ↔ Evaluator, with memory

ResearchPlanner breaks the question into Zetaris queries
→ Retriever pulls live rows via Zetaris + recalls H-MEM
→ EvidenceSummarizer connects findings across sources
→ InsightCritic checks every claim is supported — requests revision if not
→ ReportWriter (Nightshift) writes the cited recommendation.
Every handoff → JSONL trace. H-MEM mines each run so the next one starts smarter.
SPEAKER: 30s. Stress the loop: critic rejected a draft in our logs when evidence was thin — that is the difference from a pipeline.

5 · ZETARIS — HOW & WHAT'S UNIQUE

Two live REST sources, zero ETL

  • advisor.all_repo_health_table — GitHub: stars, forks, open issues, last push, license (~4s).
  • advisor.all_downloads_table — npm weekly downloads (~2s).
  • Unique: custom REST registration with headers + nested-struct flattening views; union views make a 3rd framework a 2-line change.
  • S3 sample DBs wired with LIMIT + honest sample fallback (never faked as live).

6 · METERLESS — HOW & WHAT'S UNIQUE

Memory that compounds + provider that routes

  • H-MEM in a working feature: every Zetaris result is mined into memory; next runs recall it (trace shows Recalled N memories). Sleep/ledger/audit all live in the notebook CLI.

  • Unique: evidence → memory → recommendation is one loop; the critic's revision requests also land in memory.
